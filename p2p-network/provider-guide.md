# Explore provider mode

Provider mode lets a compatible Desktop instance offer supported inference capabilities to peers. It is different from running a local model for yourself, and different from delivering a paid Smart Agent workflow through job escrow.

## Before offering compute

1. Open network settings and inspect **Provider** mode.
2. Choose only pipelines and models your machine can run reliably.
3. Review the consumer request data that will reach the provider and the outputs returned to the consumer.
4. Check model licenses, available memory, storage, connectivity and the effect on your own work.
5. Keep Desktop and the required local services available while serving requests.

Discovery does not authorize peers to browse your local files, prompts or memories. Use explicit request payloads and supported workflows.

## Understand the earnings limit

The current in-app Web3 guide states that **an independent attestation service and funded end-to-end settlement must be validated before provider rewards can launch**. Local timing records and the Service Time ledger are not proof of a withdrawable reward.

Pool entitlement needs independently verified receipts, a finalized period, available funding and unpaused provider claims. Previously earned eligible rewards survive unstaking, but running the app does not guarantee an hourly payment.

Remote agent work instead uses an owned agent and its job escrow. Funding, delivery, settlement and withdrawal remain separate steps.
